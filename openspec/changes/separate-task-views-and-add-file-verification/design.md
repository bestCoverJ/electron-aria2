## Context

当前 `getVisibleTasks` 在下载列表中包含已完成任务，同时历史记录再次筛选已完成任务，造成重复。三个视图共用单一状态筛选和任务行，导致历史记录出现双状态标签且历史/垃圾箱缺少完整筛选。终态快照依赖 aria2 返回的 `files/length`，旧记录缺少文件数组或保存了 0 长度。文件哈希尚未进入主进程数据模型。

## Goals / Non-Goals

**Goals:**

- 建立下载、历史、垃圾箱互斥且稳定的数据边界。
- 在紧凑桌面布局中提供关键词、状态/文件类型、起止日期的高级筛选和非空状态分组。
- 恢复历史文件路径与真实大小，提供单条历史记录永久删除。
- 对完成文件进行流式 SHA-256 计算并持久化，避免每轮轮询重复计算。

**Non-Goals:**

- 不验证远程服务器提供的预期哈希，也不把 SHA-256 作为下载成功条件。
- 不删除“删除历史记录”对应的本地文件。
- 不引入数据库、全文索引或第三方 MIME/哈希依赖。

## Decisions

1. 视图边界按状态集中定义：下载列表排除 `completed/removed`，历史仅含 `completed`，垃圾箱仅含 `removed`。相比在组件中隐藏重复行，集中筛选可保证计数、选择和空状态一致。
2. 使用一个 `TaskFilters` 状态对象承载关键词、状态、文件类型、开始日期和结束日期。高级筛选使用可折叠面板；状态为“全部”时下载列表按规范顺序对实际存在的状态分组，不渲染空分组。
3. 日期以任务 `updatedAt` 的本地自然日比较；结束日期包含整日。历史和垃圾箱复用同一筛选组件，但只提供对当前视图有意义的状态选项。
4. 任务行仅保留右侧 `TaskStateBadge`。文件名附近不再渲染第二个状态，三个列表统一处理。
5. 增加独立 `deleteHistoryRecord(gid)` IPC，仅允许持久化终态历史记录并删除 aria2 result/本地元数据，不触碰文件。它与“移到垃圾箱”和“清空历史”保持不同语义。
6. 终态恢复时，若文件列表为空，则从 `directory + task.name` 构造候选文件；若长度为 0，则在主进程使用文件统计修复文件长度、完成长度和任务总量。路径不存在时保留记录并显示文件不可用，不伪造大小。
7. `DownloadTaskFile` 增加 `type` 与 `sha256`。类型由扩展名映射到稳定中文类别并保留扩展名；SHA-256 使用 Node 流式 `createHash` 后台计算，结果写入任务元数据。正在下载显示“任务完成后计算”，完成但尚未完成计算显示“正在计算”，文件不可访问显示“不可用”。
8. 底部总进度先筛选 `state === "active"` 的任务，再计算已下载量、总量和百分比；没有活动下载时统一返回 `0 B / 0 B` 和 `0%`，历史、做种、等待、暂停、失败和垃圾箱任务均不参与。
9. 设置/关于页根容器仅开放纵向滚动，所有卡片和依赖表使用 `min-w-0/max-w-full` 与可换行网格，不使用强制最小表宽。
10. `AppSettings.windowBounds` 持久化普通窗口 `x/y/width/height/maximized`。窗口移动/缩放后防抖写入；紧凑模式不写入。启动时按目标显示器工作区裁剪尺寸和位置，避免显示器变化后窗口落在屏幕外。

## Risks / Trade-offs

- [大文件哈希占用磁盘吞吐] → 单任务串行、流式读取且每个文件只计算一次，不阻塞快照返回。
- [旧历史文件已移动或删除] → 保留历史记录并明确显示不可用，不将 0 B 当作真实大小。
- [日期时区边界] → 在渲染进程按用户本地自然日比较，并为日期控件提供明确标签。
- [多文件任务哈希耗时] → 每个文件独立展示计算状态，已完成的哈希先行可见。

## Migration Plan

旧 `state.json` 中新增字段均为可选。读取/投影时按路径补全文件信息，哈希在首次遇到完成任务后异步回填；回滚旧版本时额外字段会被忽略。
