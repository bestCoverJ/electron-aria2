## Why

下载列表、历史记录和垃圾箱目前没有清晰的数据边界，完成任务重复出现、状态重复展示，恢复的文件信息还会退化为 0 B 或空列表。用户也缺少按日期和状态定位任务、删除单条历史记录以及核验已下载文件完整性的能力。

## What Changes

- 下载列表仅展示未完成任务，全部状态时按实际存在的状态分组，并提供可折叠高级筛选、状态筛选和起止日期筛选。
- 完成任务自动且仅归入历史记录；历史记录和垃圾箱也支持关键词、状态/类型与日期筛选。
- 历史记录与垃圾箱任务行只保留右侧状态标签，移除文件名旁的重复状态。
- 历史记录支持永久删除单条记录，但不删除已下载文件。
- 修复旧历史任务恢复后文件大小为 0 B、文件列表为空的问题。
- 文件详情展示文件类型，并在任务完成后后台计算、持久化和展示每个文件的 SHA-256；未完成时展示状态占位提示。
- 底部总进度和累计字节仅统计正在下载的任务，不累计历史记录或其他非活动状态。
- 设置与关于页仅允许纵向滚动；普通窗口的位置、宽高和最大化状态跨启动恢复。

## Capabilities

### New Capabilities

- `task-view-organization-and-filtering`: 下载、历史和垃圾箱的数据边界、非空状态分组及多条件筛选。
- `persistent-download-file-information`: 历史记录单条删除、文件元数据恢复和 SHA-256 完整性信息。

## Impact

影响 React 工作区状态与任务列表组件、下载任务投影和持久化结构、下载 IPC、文件详情页、Node 文件统计/流式哈希逻辑及 UI/下载流程验证脚本。
